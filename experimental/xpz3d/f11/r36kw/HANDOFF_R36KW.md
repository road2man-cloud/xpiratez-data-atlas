# R36KW 인계 — 실제 수정 / 생산 / 게시 / 미완료 구분

## 실제 수정한 소스

`build_r36kw.py`: R36KV 고정 해시 입력 → 노멀 UV 70면 보완 → 명시적 탄젠트 생성 → 0가중치 관절 인덱스 정리 → GLB 생산. 기존 색상 UV와 유효 스키닝은 유지한다.

`glb_tools.py`: 현재 단일 버퍼 GLB의 읽기·속성 쓰기·활성 버퍼 재패킹. 범용 glTF 라이브러리가 아니며 압축 확장 입력은 거부한다.

`mikktspace_stage.mjs`: three.js 0.170.0에 포함된 MikkTSpace 실행. glTF W 부호 보정. 다른 tangent 구현으로 몰래 교체하지 않는다.

`viewer_r36kw.js`, `build_preview.py`: R36KV/R36KW 두 해상도 4개 모델을 포함한 오프라인 비교 뷰어. 노멀 효과와 원래 색상을 분리해 확인한다.

`review_r36kw.py`: 실제 GLB를 Edge/three.js로 캡처. 버전 라벨을 픽셀 비교에 섞지 않도록 캔버스 자체를 비교한다.

`prepare_r36kw.py`, `validate_glb.cjs`, `publish_r36kw.py`: 고정 입력 준비, GLB 형식 검사, 명시적 파일 목록으로 패키지/게시.

## 실제 생산 파일

- `output/R36KW_F11_NORMAL_UV_REPAIR_1024_2100TRI.glb`: 933,040바이트.
- `output/R36KW_F11_NORMAL_UV_REPAIR_512_2100TRI.glb`: 580,476바이트.
- 몸통/다리 노멀 PNG 2장, 공통 헤어 노멀 PNG 1장.
- 해상도별 빌드 보고서와 Validator 원본 JSON.
- `preview/index.html`, 실제 비교 캡처 13장 + 합성 포즈 캡처 1장, 렌더 보고서.

두 GLB 모두 2,100삼각형, 63본, 12프리미티브, 2,047정점이다. 이전 1,837정점보다 증가했다. 색상·거칠기 이미지, 모든 원래 코너 위치·노멀·UV·가중치, 유효 본 번호가 유지된다. 노멀 UV 면적 0인 면만 70 → 0이며 원래 색상 UV의 퇴화 면은 남아 있다.

## 수행한 확인과 적용하지 않은 것

GLB 형식 오류 0, 경고 1. headless Edge/file://에서 4개 GLB 로드와 캡처, JS 오류 0. 1024 얼굴·발·전신 albedo 캔버스 비교 차이 0. 합성 팔70°/다리32° 포즈 캡처. 이것은 실제 S2/S3 게임 실행이나 전투 애니메이션 검증이 아니다.

게임 설치폴더를 수정하지 않았고 S2/S3 런타임에 적용하지 않았다. 고밀도 원본 확보와 복원, 위상학적 몸통-다리 접합, GPU 성능 측정은 미완료다.

## 비용과 개선 우선순위

새 노멀 아틀라스 공간 때문에 RGBA8·밉 제외 면적 합계가 1024 +4.25MiB, 512 +1.25MiB 증가한다. 프리미티브/재질 수를 늘리지 않는 설계의 비용이다. 다음 작업은 이 정상 동작을 지키면서 새 패치 영역의 빈 공간을 줄이는 것이다. 드로 콜 추가나 호환성 저하로 메모리만 줄이고 성공했다고 하지 않는다.

1. R36KW와 입력 R36KV를 함께 읽고 `normalTexture.texCoord`가 가리키는 실제 UV를 기준으로 작업한다. `TEXCOORD_0`만 보고 70면이 여전히 문제라고 오판하지 않는다.
2. 기존 색상 UV·기본 색상·리깅은 보호한다. 수축 아틀라스 안의 패딩/밉 샘플 누출과 UV 재정규화를 함께 처리한다. 새 모델은 R36KW 경로를 덮어쓰지 않는 다음 버전으로 저장한다.
3. 1024/512 GLB, 같은 해상도 비교 HTML, 재생산 코드, 수치와 비용을 함께 실제 생산한다. 엔진 설치가 이루어지지 않으면 `engineApplied: false`를 유지한다.
4. 실제 S2/S3 경로를 확인할 수 있을 때만 엔진 연결을 별도 작업으로 수행한다. 원본 본 계층 경고를 없애려고 성급히 노드를 재배치하지 않는다.
