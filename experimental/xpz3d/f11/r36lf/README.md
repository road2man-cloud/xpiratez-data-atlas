## 보정 및 비용 선택

45도/90도 POSITION 모프 변화량을 6차원 벡터로 묶고 무릎별 3개 대표 벡터를 학습한다. 정점마다 최대 2개 대표 벡터의 보간을 사용하며, 각 대표 벡터에 허벅지/종아리 부모를 복제하는 보조 본 2개를 둔다. 4개 이하의 영향으로 원래 스키닝과 보정 이동을 근사한다. 무릎당 2/4개 보조 본 후보의 효과가 부족하여 6개를 선택했다. 10~95도 13개 계산 자세에서 R36LE의 RMS 로그 모서리 변형 감소량 대비 R36LF가 유지한 비율은 왼쪽 74.20%, 오른쪽 78.94%다. 이는 R36LD 대비 개선량의 상대 비율이지 절대 변형 감소율이나 시각 품질 비율이 아니다.

기존 8개 애니메이션의 모든 저장 키프레임에서 실제 출력 GLB의 CPU 스키닝 위치를 원래 모프 GLB와 비교했다. 발 굴림 걷기에서 보정 대상 정점 위치의 차이는 RMS 약 0.002115, 최대 0.006773 모델 단위다. 나머지 클립별 결과와 각도별 RMS/최대 로그 변형은 BUILD_REPORT에 기록한다. 원본과 정확히 동일한 모프 재현은 아니다. POSITION 변화만 근사하며 원래 NORMAL/TANGENT 모프 보정 효과를 복제하지 않는다.

## 적용 조건

모프를 지원하지 않더라도 75개 관절과 정점당 4개 영향, 보조 본 translation 트랙을 지원하는 엔진이어야 한다. 63/64개 관절 제한 엔진의 호환을 주장하지 않는다. S2/S3의 실제 규격은 미확인이다. 외부 게임 애니메이션에는 보조 본 트랙이 별도로 필요하다. R36LF_HELPER_MAP.json에 본 매핑 및 바인드 공간 보정 벡터를 포함한다. 기존 R36LE의 각도별 가중치 함수와 부모 본 바인드 회전 역변환으로 보조 본 이동량을 산출할 수 있다. 외부 엔진용 런타임 드라이버 자체는 구현하지 않았다.

## 재생산

Python 3.9 이상, numpy, scipy, Pillow. 입력 GLB가 없으면 python prepare_r36lf.py, python build_r36lf.py로 모델 및 보고서를 생성한다. python publish_r36lf.py는 ZIP 생성, --publish는 인증된 gh로 새 GitHub 경로에 게시한다. 기존 버전은 덮어쓰지 않는다.

내부 컨테이너에서 raw.githubusercontent.com DNS 조회 실패 후 C:\mnt\data\r36lf_work 격리 Windows 작업공간에서 생산했다. 실제 게임 실행폴더는 변경하지 않았다. S2/S3 로딩, 렌더링, 관절 수 제한, GPU 성능, 외부 게임 모션 연결은 미완료다. 후속 작업은 63본 제한과 모프 지원 여부에 따라 적합한 버전을 선택할 수 있도록 실제 엔진 모델 로더와 연결하는 것이다.
