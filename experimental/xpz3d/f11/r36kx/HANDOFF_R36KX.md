# R36KX 다음 작업자 인계

## 실제 수정 소스

- `build_r36kx.py`: R36KW 노멀 픽셀/패치 정수 좌표 재배치, 기존 정점별 TEXCOORD_1 수정, 보호 속성 검사, GLB 2종 출력.
- `prepare_r36kx.py`: 고정 커밋 입력 GLB·패치 메타데이터·헬퍼·Node 잠금 파일 회수. GLB SHA-256 고정.
- `viewer_r36kx.js`, `build_preview.py`: 독립 실행 HTML 비교, 동일 해상도 비교, 원거리·밉 필터 선택, 현재 GLB 저장 기능.
- `review_r36kx.py`: 화면 라벨을 제외한 실제 WebGL 캔버스 비교. GLB 내보내기 바이트 대조.
- `validate_glb.cjs`: 포맷 보고서 생성.
- `publish_r36kx.py`: 새 경로만 게시, 최신 main 위에 트리 구성, force push 금지, 게시 저널·원격 바이너리 대조.
- `glb_tools.py`: R36KW 고정 커밋에서 가져온 헬퍼. 이번 형상 작업으로 수정하지 않음.

## 실행과 게시 상태 구별

생성 GLB 2종과 WebGL2 오프라인 뷰어 실행 완료. 선택한 14개 PBR 비교에서 최대 채널 차이 1/255, 양 해상도 전신 albedo 비교 차이 0, JavaScript 오류 0. Validator 오류 0/경고 1/정보 4. 실제 보고서는 `output/*REPORT.json`, `output/*VALIDATOR.json`, `preview/RENDER_REPORT.json`.

GitHub 게시 성공 여부와 커밋은 `PUBLISH_RECEIPT.json`을 읽을 것. 문서만 보고 업로드 완료를 추정하지 말 것. 업로더가 실행 중이었다면 `PUBLISH_JOURNAL.json`과 원격 ref를 먼저 확인하고 불명확한 쓰기를 재실행하지 말 것. GitHub 게시와 Pages 배포와 게임 적용은 별개.

S2/S3 실제 NPOT 지원/리사이즈 정책, 렌더러 실제 텍스처 할당량, 전투 애니메이션, 프레임레이트, 몸통-다리 위상 접합, 고밀도 참조 메시 복원. 게임 설치폴더 변경하지 않음. 정상 텍스처 픽셀과 밉 필터의 모든 결과까지 동일하다고 주장하지 말 것.

## 다음 구체적 실행

1. R36KX를 기반으로 실제 S2/S3 임포트·재질 경로를 먼저 확인하고, NPOT 이미지를 자동 확대하는지 확인한다. 지원이 확인되기 전에는 기존 R36KW를 삭제하거나 자동 대체하지 않는다.
2. 실물 개선 우선순위는 런타임의 중복 텍스처 자원 공유다. 이번 three.js 뷰어에서 이미지 9장에 대응하는 Texture 객체는 14개였다. 이것이 GPU 할당 14개라는 증거는 아니므로 업로드 핸들/이미지·색공간·샘플러·UV 채널 키를 구분해 실제 로더를 개선한다. 색공간이 다른 맵을 무조건 합치지 않는다.
3. 기존 피부색, 70개 정상 노멀 영역, 63본, 2,100삼각형을 보호한다. 같은 빈 픽셀 압축을 반복하여 새 디테일 생산이라고 보고하지 않는다.
4. 고밀도 원본을 확보한 뒤에만 실제 베이크 복원을 추진한다. 이번 버전은 공간 정리이지 6,044삼각형 공여 메시 복원이 아니다.
