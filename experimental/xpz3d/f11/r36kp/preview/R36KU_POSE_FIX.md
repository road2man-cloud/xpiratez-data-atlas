# R36KU — 허벅지 벌림 방향 수정 · R36KP 계열 대시보드

## 결론

기존 슬라이더는 **왼쪽 +Y / 오른쪽 -Y 회전**을 적용해 무릎을 안쪽으로 이동시켰다. R36HW/R36JB 골격의 실제 로컬 좌표에서 왼쪽 허벅지 관절은 +X에, 오른쪽은 -X에 있고, 무릎은 각각 해당 허벅지의 -Z 방향에 있다. **왼쪽 -Y / 오른쪽 +Y** 회전이 외전(abduction)에 해당한다. 이 부호를 공통 함수로 바로잡았다.

- 공통 코드: `r36kp/preview/pose-spread.mjs`
- 적용한 UI: `r36kp/preview/index.html`, `r36kp-texture-lab-20261127/{r36kq,r36kr,r36ks,r36kt}/preview/index.html`
- UI 추가: **0° / 18° / 35°** 프리셋, 실제 무릎 사이 거리 표시(모델 단위)
- 골격 전환이나 화면 모델 교체 시 이전 포즈가 누적되지 않도록 *bind quaternion을 먼저 복원*한다.
- GLB 메시, 스킨 가중치, 2048 텍스처, 총 2,088삼각형은 변경하지 않았다.

## 실제 브라우저 결과

Chrome WebGL 로딩 후 0° → 18° → 35° → 0° → 35° 순서로 움직인 실제 GLB의 `L_Leg` / `R_Leg` 월드행렬을 측정하였다.

| 설정 | 무릎 간 거리 (모델 단위) |
|---|---:|
| 0° | 0.179791 |
| 18° | 0.452660 |
| 35° | 0.686273 |

35°에서 왼쪽 무릎은 +X로 약 **0.253241**, 오른쪽 무릎은 -X로 약 **0.253241** 이동했다. 다섯 대시보드 모두 통과했고, 각도를 0°→35°로 재설정했을 때 같은 위치를 재현했다.

- 자동 시험: `r36kp/preview/test-thigh-spread.cjs`
- 계측 결과: `r36kp/preview/POSE_REGRESSION_REPORT.json`
- 캡처: `r36kp/preview/captures/R36KP_SPREAD_0.png`, `R36KP_SPREAD_35.png`

## 예외 처리

공통 모듈은 향후 골격에서 좌우가 반전될 수 있는 경우에 대비해 회전 결과의 좌우 무릎 이동 방향을 측정한다. 한쪽이 안쪽으로 이동하면 반대 회전 부호를 비교하여 **양쪽 무릎 모두 바깥쪽으로 움직이는 쪽**을 선택한다. 누락된 골격을 발견하면 수치를 꾸며 표시하지 않고 측정을 건너뛴다.

## 재현

F11 루트에서 로컬 HTTP 서버를 띄우고(기존 대시보드 공유 서버 포트 9400) Chrome 디버그 포트 9341을 연결한 상태에서 다음 명령을 실행한다.

```bash
node experimental/xpz3d/f11/r36kp/preview/test-thigh-spread.cjs
```

실제 게임 엔진 적용이나 전투 모션의 유효성까지 확인한 것은 아니다. 기존 모델의 **관절 스킨 변형에 따라 골반에 각진 그림자/틈이 남는 현상도 별도 미완료**이며, 텍스처만으로 비어 있는 표면을 복구할 수는 없다.
