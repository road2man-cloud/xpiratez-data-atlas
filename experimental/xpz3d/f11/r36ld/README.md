## 생산 방법 및 결과

어깨와 팔꿈치, 무릎 6개 영역을 국소 본 쌍의 스키닝 후보로 평가했다. 실제 모델의 기존 대기/걷기/준비 동작 샘플과 합성 관절 스트레스 자세를 사용했다. 각 영역에서 20~22개 자세에 대해 국소 모서리 길이의 로그 변형량, 최악 자세의 RMS, 어깨 인접 메시 간 거리 변화를 비교해 개선되는 후보만 채택했다. 동일 위치·가중치를 가진 UV 중복 정점은 함께 수정한다. 어깨는 몸통과 덮개 사이 8개의 근접 쌍을 이용하여 가중치를 조정했다. 이 쌍은 거리로 선정한 근접 대응점이며 위상적으로 접합된 경계라는 뜻이 아니다.

| 부위 | 변경 정점 레코드 | RMS 로그 길이 변형 전→후 | 최대 절대 로그 길이 변형 전→후 |
|---|---:|---:|---:|
| 오른쪽 어깨 | 62 | 0.13036→0.10462 | 1.37690→0.56588 |
| 왼쪽 어깨 | 68 | 0.13313→0.10141 | 1.41410→0.52268 |

| 왼쪽 팔꿈치 | 11 | 0.04684→0.04652 | 0.45248→0.26343 |
| 양쪽 무릎 | 0 | 변화 없음 | 변화 없음 |

오른쪽/왼쪽 어깨 근접 쌍의 최대 거리 변화는 0.0025405→0.0017286, 0.0090524→0.0022831 모델 단위로 감소했다. 무릎 후보는 개선 기준을 충족하지 않아 원래 가중치를 유지했다. 수치는 각 영역의 후보 채택 단계에서 계산한 CPU 스키닝 지표다. 실제 표면 부피, 화면상 관절 자연스러움 또는 모든 게임 자세의 개선을 증명하지 않는다. 거리 변화가 줄었다고 실제 메시의 빈틈이 완전히 없어졌거나 위상 접합이 완료된 것으로 표시하지 않는다.

## 재생산
Python 3.9 이상, numpy, scipy, Pillow. ZIP에 입력 GLB를 함께 포함한다. 없으면 python prepare_r36ld.py를 실행한다. python build_r36ld.py는 두 GLB와 영역별 보고서를 생성한다. python publish_r36ld.py는 묶음을 생성하고 --publish 지정 시 새 GitHub 경로에 게시한다. 기존 버전은 덮어쓰지 않는다.

제작 경로 C:\mnt\data\r36ld_work. 내부 컨테이너에서 raw.githubusercontent.com DNS 조회가 실패하여 격리 Windows 작업공간을 사용했다. 실제 S2/S3 엔진 적용, 렌더 비교, 위상 접합, 무릎 추가 개선은 미완료다. 게임 실행폴더는 변경하지 않았다. 후속은 합성 자세뿐 아니라 원본 엔진 애니메이션을 확보하여 관절의 실제 형상과 이음새를 개선하는 작업을 우선한다.
