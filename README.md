# X-Piratez Data Atlas

X-Piratez [아이템 DB](./public/items/) · [연구 DB](./public/research/) · [병사훈련·조합 DB](./public/trainings/) · [기지시설 DB](./public/facilities/) · [기체무장 DB](./public/craft-weapons/) · 방어구·병종·탈것을 **검색·정렬·비교**하고, 상세 화면에서 실제 적용 핵심 스펙, 원본 룰 필드, 연구/제조/이벤트 역참조를 확인할 수 있는 정적 웹 DB입니다. 병종과 탈것은 획득 방식, 해금 연구트리, 명목 누적 연구량, 분기 전용 조건, 표본/기지 기능/기간 제한 같은 특수조건까지 추적합니다.

## 버전별 자료의 적용 범위

**기존 무기·아이템·연구 등 정적 DB는 X-Piratez v.o1.1.1 / OXCE 8.6**이지만 **현재 병종 DB는 X-Piratez 2.1 / OXCE 8.7.1만 제공합니다.** 별도 `public/reference/` 엔진 번호표 및 직접 경험치 선언 아이템 306개도 최신 설치본을 기준으로 합니다. 동일한 내부 ID라도 버전 사이에서 스펙, 연구 선행, 해금, 저항, 경험치 및 전투 스크립트의 일치를 가정하지 마세요. 참조표의 최신 엔진 규칙을 기존 DB 수치에 적용하는 계산은 2.1 게임에서 검증된 계산이 아닙니다. 사이트 내 각 페이지의 버전 안내를 먼저 확인하세요.

## 기준 데이터

- X-Piratez: **v.o1.1.1**
- OXCE 요구 버전: **8.6**
- 현재 생성 결과: **4,007 items / 4,612 research / 957 armors (496 store-item armors) / 29 base Soldier rules / 72 acquisition profiles / 83 soldier transformations / 998 soldier bonuses / 96 crafts / 155 craft weapons / 115 facilities / 2,158 manufacture / 4,972 ufopaedia records**
- 한국어 이름은 모드의 `Language/ko.yml`, 영문은 `Language/en-US.yml`에서 해석합니다.
- 이미지·음원·맵 등 원본 게임 자산은 포함하지 않습니다.
- UFOPEDIA 장문 본문은 저작권이 있는 원문 재배포를 피하기 위해 기본 생성물에서는 제외합니다.

## 모든 DB의 간결한 플레이 판단

공개된 **14개 DB / 정적 원본 16,391개 항목**에 **요약 · 판단** 버튼을 공통 제공하며 목록에서 한 줄 결론을 미리 보여줍니다. 클릭하면 **한눈에 보는 결론 → 실제 효과 → 해금·자격·비용 → 실행 방법 → 언제 가치가 있는가 → 주의·예외** 순서로 설명합니다. 기존 검색·정렬·세부 수치·원본 근거·상호배타 조합기의 판정은 유지합니다.

**데이터 생성:** npm run build:play-guide (기존 룰셋 정규화 데이터와 연구·아이템·제조·이벤트·적부대 editorial sidecar에서 생성). **검증:** npm run check:play-guide (14개 DB의 전체 원본 ID와 가이드 1:1 대응·필수 필드·Captain's 11 원본 이벤트/변신/특성 교차 확인). 두 명령은 패키지에 등록되어 있고, 가이드 검증은 통합 npm run check 및 Pages 배포 게이트에 포함됩니다.

연구를 **요구**하는 이벤트와 연구를 직접 **지급**하는 이벤트, 직접 병사 스탯과 별도 SoldierBonus, 훈련의 방향성 상호배타와 후속 훈련 봉쇄를 구별합니다. 이 요약은 **원본 기반의 정적 플레이 해석**이지 현재 세이브를 실행한 실측·게임 내부 예외의 전수 증명이 아닙니다. 연구 완료·시설·재료·분기 충족 및 병종의 실시간 최종 강화 조합은 기존 상세 정보·시뮬레이터에서 따로 검증해야 합니다.

## 통합 병종 DB의 X-Piratez 2.1 검증 옵션 (OXCE 8.7.1)

[병종 DB](./public/soldiers/)는 **X-Piratez 2.1만 표시하는 단일 진입점**입니다. 과거 1.1.1 병종 목록은 화면에서 제거하고 기존 `/soldiers/` 및 구버전 깊은 링크는 최신 2.1 병종 화면으로 연결합니다. 2.1의 112개 획득 관련 분기·능력치 검증이 기본 화면이며, 29개 기본 바디 규칙·83개 변신·훈련·연구 상호배제와 세이브 분석은 필요할 때 펼치는 상세 도구입니다. 과거 29종의 정적 최대치 후보 표는 오류를 유발하는 중복 화면이므로 사용자에게 제공하지 않습니다. 내부 검증용 감사 원본은 원본 불일치·허위 인증 회귀검사를 위해 남겨둡니다. 이 2.1 검증 화면은 **현재 설치된 X-Piratez v.o2 / OXCE 8.7.1 룰셋으로 별도 생성한 데이터**를 사용하고, 별도 보존된 과거 v.o1.1.1 검증 데이터와 최신 v.o2 병종 수치를 섞지 않습니다. 최신 전용 데이터는 `public/data/soldiers-modern-index.json`에 저장하며 29개 바디, 72개 획득형, 83개 변신, 연구 4,654개, 병사 허용 방어구 540개, 훈장 110개를 포함합니다.

**획득처별 최대치 감사:** 기존 동일 페이지의 [획득처별 출생 상태·성장·검증 표](./public/soldiers/modern/#originMaxima)는 72개 독립 출생 원본과 40개 병종 전환 입구(총 112개 색인 분기)를 분리합니다. 출생 능력치·기존 이력·보너스·체육관/전투 성장의 낙관적 상계는 표시하지만, 전체 연구→획득→훈장→변신 시간순 재생이 통과하지 않은 **최종 11개 능력치 및 그 합계는 게시하지 않습니다(현재 0개 확정)**. 기존 29병종 +411 등의 정적 후보는 화면에서 폐기하고 내부 출처 검증용 자료로만 보존해 획득처별 최댓값과 혼동되지 않도록 합니다. **제조의 `requiredItems`와 이벤트 `eventScripts`의 대체 출처·월·확률·긍정/부정 가드는 설치된 v.o2 룰셋에서 직접 생성하며, 역사적 v.o1.1.1 제조/이벤트 DB를 같은 ID만으로 결합하지 않습니다.** 여러 이벤트 스크립트는 서로 다른 대안으로 분리하고 일회성 여부를 달력 범위에서 추정하지 않습니다. 최초 출생처부터 시작하는 다단계 병종 변경만을 별도 열거해 **401개 구조 후보(최장 5단계)**를 원본 획득처 화면에서 확인할 수 있습니다. 이는 연구·전투성장·훈장·재료·사망 후 상태가 실제로 충족되는 완전한 육성 경로가 아닙니다. 또한 같은 페이지에서 일반 캠페인 훈련 73종을 대상으로 **하나의 추가 훈련과 필수 선행 훈련**을 출생 직후 또는 병종 변경 사이에 삽입하는 제한적 감사를 표시합니다(구조 순서 22,686건, 실행 검증 0건). 일반 농부/반 슈퍼변이체 농부/테베 돌격클론의 서로 다른 출생 이력과 훈련 차단, 보너스 중복·`reset:true` 이후 소멸, 원본 연구·재료·계급·훈장·시설 요건을 분리합니다. 이 경로별 수치는 실제 최종 능력치나 포괄적 훈련 조합의 확정 최대치가 아닙니다. **신규 능력치·하드캡 시간순 감사에서는 출생 72개, 출생처 기점 변신 사슬 401개 및 각 사슬의 훈련 한 종류 추가 401개(총 3,559개 계산 단계)를 조사**합니다. 각 단계의 원시 현재 능력치 범위·실효 현재 능력치 범위·실제 병종 원시 성장 `statCaps`·체력훈련 `trainingStatCaps`·중복 제거 영구 보너스·참조용 실효 상한을 구분하고, 연구·재료·계급·훈장·시점·RNG·전투 성장 및 전역 최적성 완결 증명 전에는 확정으로 인정하지 않습니다. **웹 화면의 기본 모드는 '확정 최종 능력치만'이며 현재 확정값 0개는 공란으로 표시**합니다. **증명 우선 리뉴얼:** [기존 2.1 획득처 증명 원장](./public/soldiers/modern/#originMaxima)에서 112개 획득 분기 각각의 10개 검증 관문과 미증명 사유를 확인하고 직접 모집·제조·이벤트·병종 변경, 출생 이력 충돌, 이력 초기화 등을 필터링할 수 있습니다. 과거 29병종 +411 등의 미증명 이론값은 사이트에서 더 이상 조회할 수 없습니다. 원본 버전·파일·출생처·하드캡 검사가 실패하면 **유일한 획득처별 능력치 표 전체를 차단**하며, 과거 숫자로 대체하지 않습니다. 게시 검증은 `tools/check-soldier-origin-publication.mjs`와 Chrome/Edge·CI 브라우저 오염 테스트로 확인합니다. 전체 연구·훈련·훈장·성장·변신 경로의 실제 실행과 전역 최적성은 아직 0건 증명으로 유지합니다.

**연구 순서 필요조건 감사(2026-11-02):** 같은 2.1 출생처 원장에 **72개 출생 + 401개 병종변경 + 401개 단일 일반 훈련 삽입**을 대상으로 필수 연구의 **가상 즉시 지급 → 단계별 원본 `disables` 적용** 검사를 통합했습니다. 이벤트 출생 분기를 별도 재생하는 **887회 순서 후보 검사(이벤트 스크립트 38회 포함, 반복 경로 중복 포함)**와 **3,731회 필수 연구 지급 가정(중복 포함)**에서 직접 필수 연구 폐쇄 충돌은 0건입니다. 이는 연구실의 `dependencies`·`unlocks`·자동 비용 0 연구·무료 추첨·이벤트·재료·시설을 실제로 실행한 증거가 아닙니다. 기존 페이지의 획득처별 상세에서 연구별 의존성·표본·지급 대안과 순서를 확인할 수 있고, **허위 연구 실행 판정·이벤트 대안 혼합·적색/녹색 코덱스 배제 위반을 잡는 회귀검사**가 배포 게이트에 추가됐습니다. 최종 능력치 확정 0개는 유지합니다.

- 변신 실행 순서, 필수/금지 이력의 방향성, 초기 획득형의 이전 변신 기록, 병종 변경 후 계급 자동 강등·승진 가능 여부, 연구 영구 폐쇄·대체 해금, 생존·부상·훈장·스탯·재료를 검사합니다. 연구 플래그 `STR_UNAVAILABLE`이 필요한 3개 내부 전용 변신은 일반 캠페인의 후보에서 자동 제거합니다. 훈장 요구 등급 0도 해당 훈장의 실제 보유를 요구합니다.
- **세이브는 사용자의 브라우저에서만 읽습니다.** v.o2 / Extended 8.7.1 버전 확인 후 완료/폐쇄 연구와 현재 대원 및 완공 시설·현재 재료·훈장·능력치 등을 판정에 활용합니다. 개인정보가 담긴 `.sav` 파일은 서버에 전송하지 않습니다. 테스트용 허구의 소형 세이브만 저장소에 포함됩니다.
- 방어구는 **한 벌만 착용**하고, 동일 SoldierBonus 특성은 중복 합산하지 않습니다. OXCE 실효 전투 능력치는 원시 능력치+모든 특성 보너스+장갑 보정 합산 후 최종 최소값을 적용하며, Psi 기술의 훈련 자격 판정과 실제 전투 표시는 구분합니다. 정확한 장비·훈장 보너스 증거가 없으면 현재 실효 능력치를 확정하지 않습니다.
- 일반 갈(`STR_SOLDIER`)과 반 슈퍼변이체 농부(`STR_HALF_UBER_GIRL_RECRUITMENT`)의 **83개 변신 전수 비교표**에서 서로 다른 28개 판정 유형을 필터로 확인할 수 있습니다. 일반 갈은 병종 계보 43개 + 내부 전용 2개 = 45개 확정 제외입니다. 반 슈퍼변이체 농부는 병종 계보 31개 + 내부 전용 3개 + 이력·선행변신의 도달 불가 11개 = 45개 확정 제외입니다. 각각 남은 38개는 **실제 획득 확정이 아니라 추가 조건 탐색 대상**입니다. 병종 변환 순서에서 모든 경로에 반드시 남는 과거 변신의 교집합을 고정점으로 계산해, 스펙터→일반 갈을 거쳐야 하는 농부의 후속 변신을 무작정 허용하지 않습니다.
- 현재 캠페인에서 사용자가 선택한 세이브의 완료·폐쇄 연구를 비교표에 직접 대조합니다. **명목 선행 연구가 폐쇄된 것과 변신의 직접 요구 연구가 영구 폐쇄된 것은 다른 판정**입니다. 현재 폐쇄 연구의 선행망 충돌만으로 영구 불가능을 선언하지 않고, 794개 이벤트 규칙에서 추출한 직접 연구 지급 근거(현재 색인 1,146개 연구 플래그)를 조건부 지급 후보로 표시합니다. 동일 변신이 동시에 요구하는 두 연구가 서로 영구 폐쇄하는 경우는 별도 확정 차단합니다.
- 실제 `35_.sav`를 공개하지 않고 로컬에서 53명·연구 상태를 교차 검사한 결과, 각 병종 38개 미래 후보 중 이미 완료된 요구 연구는 4개씩이고 직접 요구 연구의 폐쇄는 0개입니다. 명목 선행망 충돌은 일반 갈 7개, 반 슈퍼변이체 농부 4개이며 **획득 불가 확정이 아닌 미확인 조건**으로 표시합니다.
- **선택한 변신 순서의 12종 능력치 안전 범위**: 현재/초기 생성값의 원본 최소·최대, 퍼센트 변화의 정수 절삭, 용기 10단위 반올림, 신체 변경 후 최소값/성장캡, 소프트/하드 상한, 무작위 Flat 증가량, 대상 병종 재굴림을 보수적인 구간 연산으로 계산합니다. 기존 2.1의 변신 83개 중 능력치 무작위 변화 범위를 갖는 것은 `STR_REVOLUTIONARY_TRAINING` 1개이며, 반 슈퍼변이체 농부의 사격 60→45~70 / 체력 45→39~54가 원본 산식과 일치함을 확인했습니다. 420개 독립 작은 수치 조합을 전수 확인해 범위가 실제 게임 결과보다 좁아지지 않음을 검사합니다. RNG 결과에 따라 다음 변신의 자격이 달라지면 확정 가능 대신 **조건부**로 표시합니다. 실제 세이브 53명 전원의 정확한 원시 능력치를 읽고, 장비·훈장까지 확인 가능한 42명에만 실효 능력치를 표시합니다. 무기별 숙련 훈장의 세부 등급이 불완전하면 임의 보너스를 합산하지 않습니다.
- **전투/체력훈련 성장 단계를 변신 전후 임의 순서로 가정**할 수 있습니다. OXCE `postMissionProcedures`에서 주능력치의 최대 6점 정산은 성장캡 +5까지, 용기 +10 정산은 성장캡 +9까지, 보조 성장 정산은 성장캡 +1까지의 상계가 됩니다. 체력훈련은 두 종류의 캡(전투·훈련)과 현재 체력 상태를 따르고 성공 때 +1이므로 상한을 초과하지 않습니다. 설치된 2.1의 41종 방어구에는 임무 종료 5~20% 보조 성장 스크립트가 있으며, 그 효과도 `cap +1` 경계를 넘기지 않음을 독립 수치 조합 55,510건으로 검사했습니다. Mana는 해당 2.1 설치의 `trainingPrimary`/`trainingSecondary` 플래그를 사용합니다. 이 계산은 **미래 XP를 무한히 얻는다는 가정 아래 상한을 넓히는 것**이지 실제 성장 달성·시간·Psi 해금·이벤트·무기별 장비 입수를 보장하는 결과가 아닙니다. 전투 성장 후 변신과 변신 후 성장을 구별하고, 그 다음 능력치 자격 판정도 구간으로 계산합니다.
- 실제 `35_.sav`의 53명 원시 능력치에는 현재 바디의 성장캡을 이미 넘은 수치가 48건 있습니다(동일 대원이 여러 건 보유 가능). 미래 성장 상계 계산도 해당 초과값을 보존하며, 성장캡을 하드 클램프로 사용하지 않습니다.
- **동일 대원의 미래 경로 제한 자동 탐색**: 선택한 목표 변신을 실제 저장본의 연구 완료/폐쇄·같은 기지 재고·자금·현재 병종·변신 이력에 맞춰 연구→제조→변신 순서로 자동 탐색합니다. 직접 연구, 보호 무료 연구, 조건부 이벤트 출처를 구분하며 실제 스텝을 `verifyCampaignSequence`로 재생합니다. 무료 보상은 연구 완료 시점의 1회 지급 후보이고, 과거 완료 연구의 보상을 임의로 중복 사용하지 않습니다. 클론은 원본 대원의 동일인물 강화로 합산하지 않습니다. 세이브의 `generatedEvents` 일회성 이력을 브라우저에서 판독하며, 누락 시 이미 일어나지 않았다고 가정하지 않습니다. 비용 0인 자동·이벤트 연구도 연구실에서 직접 실행 가능하다고 추정하지 않습니다. **확정 제외는 엔진의 병종/필수 이력 증명에 한정**하고, 제한 탐색에서 경로가 없으면 반드시 '미확정'으로 표시합니다. 9개 독립 자동 탐색 시나리오, 캠페인 재생 15개, 이벤트 시간순 19개 회귀 검사를 포함합니다.
- **시간순 경로의 조건부 탐색 확장**: 월별 이벤트의 향후 양수 가중치 창을 찾아 다음 이벤트 발생 가능 월을 조건부로 검토하고, 확률 제조 `randomManufacture`가 목표 변신 재료를 줄 수 있는 경우를 별도 가정 경로에 포함합니다. 월 진행 시 기지 유지비·외부 이벤트를 재생하지 않으므로 그 경로는 절대로 확정 증명으로 표시하지 않습니다. 확률 제조도 보상 가중치와 실제 재료 소모를 검증하지만 RNG 결과를 보장하지 않습니다. 하나의 제조법이 동일 아이템에 서로 다른 수량·가중치 출력을 갖는 경우에는 현재 재생기가 출력 변형을 정확히 지정할 수 없으므로 탐색을 보류합니다. 반복 변신 목표의 요청 순서를 보존하고 종료 월을 넘긴 이벤트는 되살리지 않습니다.
- **비용 0 자동 연구 선행조건 진단**: OXCE `SavedGame::getAvailableResearchProjects()`와 `addFinishedResearch()`의 조건을 근거로 비용 0인 연구 2,040개를 일반 연구실 직접 연구와 구별합니다. 그중 변신 83개가 직접 요구하는 비용 0 플래그는 11건(내부 전용 3건 포함)이며, 선택한 실제 세이브에서 필요한 선행 연구, 같은 기지의 실물 표본, 기지 기능, 연구 폐쇄 및 이벤트 직접 지급 출처를 표시합니다. 보호된 비용 0 연구의 직접 `unlocks` 예외와 과거 연구 완료 뒤 소급 지급 불가도 구별합니다. **자동 처리 후보 판정은 실제 완료 증명이 아니며** 기존 시간순 경로의 확정·미확정 결과를 임의로 변경하지 않습니다.
- **비용 0 연구 연쇄 완료의 조건부 큐 시뮬레이션**: 실제 OXCE 8.7.1 `SavedGame::addFinishedResearch` / `getAvailableResearchProjects` 순서대로 원천 연구 완료 후 인접한 비용 0 연구의 종속성, 직전 큐 항목의 `unlocks`, 보호 `requires`, 현재 폐쇄·재활성화, 같은 기지 실물 표본·시설, 이미 진행 중인 연구를 검사합니다. 조건부 처리 순서와 미증명 전제를 선택한 변신의 자동 경로 화면에 표시합니다. 반복 연구·기존 완료 연구의 소급 지급, `getOneFree` RNG와 여러 연구 동시 완료, 현재 진행 중 연구 이력이 불완전한 경우는 **실제 완료로 인정하지 않습니다**. 원본 세이브의 연구 상태를 수정하지 않고, 기존 시간순 경로의 증명 등급을 높이지 않습니다. 연구 연쇄 전용 독립 회귀 16개를 실행합니다.
- **희귀 장비의 실제 지도 배치 증거**: X-Piratez 2.1의 지도 블록/MapScript/미션 배치를 연결해 GDX 교도소 `STR_GDX_005`, 꿈의 메아리 `STR_DREAM_ECHO`, 수수께끼 상자와 아바타 메달리온의 경로를 별도 표시합니다. 지도 블록 내 고정 배치는 해당 임무가 무조건 발생하거나 실제로 아이템을 회수한다는 뜻이 아니며, 분기 연구·지도 선택·실물 회수는 조건부입니다. 성녀 복장은 최종 병종 능력치 비교 대상에서 제외하고 원본 재료 출처만 표시합니다.
- 미래 연구 이벤트, 유동적인 물품 공급, 모든 전투에서의 XP 달성 가능성·미확인 스크립트·랜덤 재굴림, 세이브 외부 국가·지역 효과와 모든 가능한 연구·선장 선택의 조합은 완전 증명되지 않았습니다. 정적 계보로 갈 수 없는 것과 현재 세이브로 확인한 미충족 조건은 자동 판정하지만, **조건부 후보를 획득 확정으로 표시하지 않습니다.** 이론적 최종 수치의 완전 검증을 선언하지 않습니다.

로컬 2.1 데이터 재생성: `node tools/build-data.mjs --source "<X-Piratez 2.1 모드 폴더>" --soldiers-modern-only`. 전용 QA: `npm run check:soldiers:modern`, `npm run check:soldiers:modern:browser`. `npm run check`에도 포함되어 있으며, 공개 Pages 배포의 브라우저 게이트도 확인합니다.

## 병사훈련·상호배타 조합 DB

[병사훈련 DB](./public/trainings/)는 **X-Piratez 2.1 / OXCE 8.7.1 전용**으로 제공됩니다. 같은 원본 [병종 DB](./public/soldiers/)의 `soldiers-modern-index.json`을 직접 사용하며 별도 1.1.1 훈련 룰을 섞지 않습니다. 72개 출생 프로필 중 실제 획득처를 먼저 선택하고, 83개 최신 훈련·개조·변신을 검색·필터링합니다. 29개 기본 병종 규칙이 같더라도 돌격클론과 농부의 출생 능력치·계급·보너스·변신 이력을 합치지 않습니다.

첫 화면에는 훈련 검색, 획득처, 판정과 필요할 때 펼치는 세부 필터만 배치합니다. 훈련을 선택하면 엔진 기준 필수·금지 이력, 연구 `requires`/우회/폐쇄, 필요 계급·훈장·능력치·재료·기지 기능과 직접 변화량·영구 SoldierBonus를 분리해 표시합니다. 훈련 순서 조합은 동일 병사의 **가상 단계**로 기록하며, 복제는 다른 병사로 취급하고 `reset: true`로 제거되는 이력을 재사용하지 않습니다. 실제 `v.o2` 세이브는 브라우저 안에서만 읽어 현재 대원의 연구·자원·훈장·변신 이력을 반영합니다. 가상의 후속 단계에는 원래 시점의 재고와 훈장 증명을 소급 적용하지 않습니다.

**증거 구분:** 원본 규칙 확인 → 현재 세이브 조건 확인 → 조건부 미래 경로는 서로 다른 검증 단계입니다. 연구·이벤트/RNG·전투 성장·재료·시설·실제 완료 시점이 모두 검증되지 않은 훈련 계획은 실행 인증도, 11종 최종 최대 능력치 인증도 아닙니다. 기존 1.1.1의 공개 병종·훈련 UI 자산을 제거했으며, 다른 구형 DB의 수치 회귀검사에 필요한 역사적 계산 코드만 `tools/legacy-*-ui.js`에 격리했습니다. 검증: `npm run check:trainings`, `npm run check:trainings:browser` 및 `npm run check:all`입니다.

## 무엇을 보여주나

목록 화면은 한글명/영문명/내부 ID, 종류, 무게, 구매가/판매가, 위력, 피해형, 사격 명중/TU, 연구·제조 연결 수를 정렬할 수 있습니다. 상세 화면은 호환 탄약, 이 탄약을 쓰는 무기, 연구·제조 관계, 다른 룰셋에서 해당 아이템 ID가 참조되는 위치, 최종 병합된 **item 룰 객체 전체**를 보여줍니다. 픽셀·스프라이트·애니메이션·사운드 같은 표현 리소스 필드는 핵심 룰 JSON과 분리 저장하고 상세 화면에서 필요할 때만 별도 로드합니다.

특히 `refNode` 상속을 먼저 펼치며, 룰에 생략된 핵심값은 OXCE의 엔진 기본값과 X-Piratez 전역 보정값을 별도로 계산해 “실제 적용값”으로 표시합니다. 각 핵심값 옆에는 **아이템 룰 / OXCE 기본값 / X-Piratez 전역값** 중 어디에서 왔는지도 표시합니다. 희귀 필드는 UI에 별도 해설이 없어도 원본 필드 테이블에 보존됩니다.

연구 탭은 직접 선행, 후속 연구, 명시 해금, 무료 획득, 실물 표본 필요/소모 여부, 아이템/제조/기타 룰 역참조를 추적합니다. **복수 선행 · 분기 배제 필터**는 원본 4,612개 연구 중 직접 선행이 2개 이상인 1,777개를 전수 검사한 뒤, 상호배타적 선행을 동시에 기재한 42개를 보여줍니다. 전부 명시적 `unlocks` 출처가 있지만 이를 실제 접근 가능성의 증거로 취급하지 않으며, 직접 `disables`·선행 `dependencies`·우회 불가 `requires`·대체 해금 연구를 근거와 함께 구분합니다. **대체 해금 출처 자체에도 상호배타적 명목 선행이 있는 8개 연구(관련 연결 16개, 고유 출처 7개)**는 별도 필터로 표시하고, 분기 시뮬레이터에서 출처별 완료·직접 차단·경로 위험을 재검사합니다. 또한 `STR_CAPTAIN_GOLD_UP`처럼 연구 완료 시 자신을 `disables`해 완료 플래그가 사라지는 연구는 지속적인 해금 출처에서 제외하며, 이 예외가 영향을 주는 목표 연구 3개를 별도 필터로 표시합니다. 더 깊은 재귀 연구망에서는 **명목 선행 순환 7그룹·95개 연구**를 확인했고, 원본 이벤트 DB의 직접 연구 지급과 `unlocks`/`getOneFree`의 외부 진입 후보를 찾아 순환 고리 증거와 함께 표시합니다. 순환 연구를 실제 획득 불가로 일괄 판정하지 않습니다.

방어구 탭은 957개 Armor 룰을 전/좌/우/후/하 방어력, 무게, 능력치 보정, 피해유형별 저항 배율, 근접 회피, 회복·위장 값으로 정렬·비교합니다. `storeItem`을 따라 실제 장비 아이템으로 연결하고 구매·제조·연구 보상·이벤트 참조를 역추적합니다. 제조법은 재료, 시설, 비용, engineer-hours를 표시하고, 선행 연구는 중복 제거한 명목 scientist-hours와 1명/10명 환산 시간을 함께 보여줍니다.

병종 탭의 기본 단위는 내부 `RuleSoldier` 29개가 아니라 **실제 획득형 72개**입니다. 직접 고용 15개, 제조/Recruitment 48개, 이벤트 생성 9개를 각각 별도 행으로 추적하고, 같은 Soldier Type이라도 `spawnedSoldier.currentStats`나 생성 시 `transformationBonuses`가 다르면 서로 다른 획득형으로 분리합니다. 자동 특성의 soldierBonus `stats`를 OXCE 엔진과 같은 순서로 합산한 **실전 생성 능력치**를 TU·기력·체력·용기·반응·사격·투척·근력·Psi·근접·Mana별 최소/평균/최대로 정렬할 수 있습니다. 29개 RuleSoldier는 내부 바디/성장 규칙 참고 탭으로 따로 두며, 초기 획득 이후의 변신·훈련은 83개 루트를 별도 탭으로 제공합니다. Saint 지원군은 31칸 가중표지만 고유 결과는 15개이며, 각 획득형에 슬롯 수와 확률을 표시합니다. Psi Skill은 기본 0이면 특성만으로 잠금 해제되지 않는 OXCE 예외도 반영합니다. 상세창에는 직접 고용·제조/Recruitment·이벤트 획득 방식, 분기 전용 여부, 명목 누적 연구량, Destructor 같은 특수 훈련의 전체 선행 연구트리를 연결합니다.

**과거 v.o1.1.1 병사훈련 데이터는 내부 회귀검사용으로만 남습니다.** 공개 화면은 위에서 설명한 2.1 원본 83개 훈련·72개 출생처와 실제 OXCE 8.7.1 세이브 검증만 사용합니다. 다른 버전의 분기 개수·재료·효과를 현재 병사에게 합산하지 않습니다.\\n\\n탈것/기체 탭은 탑승 병력·조종사·속도·연료·내구·무장·레이더·비용을 비교하고, 직접 구매/제조법과 핵심 재료의 이벤트 획득원을 연결합니다. 예를 들어 Schoolbus처럼 특정 이벤트 재료가 필요한 기체는 이벤트의 연구 트리거, 월 제한, 난이도, 기타 트리거까지 함께 표시합니다.\n\n기체무장 탭은 155개 `craftWeapons` 프로필의 weaponType, 위력·사거리·명중·탄약·재장전·재보급률·지원 스탯을 비교하고, 각 장비가 실제로 장착 가능한 기체/슬롯을 역추적합니다. `launcher`와 `clip`이 `items`의 개인 전술무기·탄약을 재사용하는지도 표시합니다. 예를 들어 `STR_CRAFT_PIR_CANNON_UC`(해적 대포)는 `STR_PIR_CANNON`(돌격대포)과 `STR_PIR_CANNONBALL`(대포알)을 재사용하지만, 기체전 위력·사거리·명중은 craftWeapon 프로필의 별도 수치를 사용합니다.\n\n기지시설 탭은 115개 effective facility 룰의 건설비·기간·월 유지비/수익·면적·숙소·창고·연구실·작업장·훈련실·격납고·포로 수용·탐지·방어를 비교합니다. 시설의 `provideBaseFunc`와 연구/제조/시설의 `requiresBaseFunc`를 양방향 역추적해 “이 시설을 지으면 실제로 무엇이 열리는가”를 표시하고, 전체 선행 연구망·건설 재료·파괴/개조 상태도 함께 보여줍니다.

영구 선택·분기 DB는 초기 5선장부터 PUSSY 클래스·Unclassed 혼합형·Pure/Ultimate, Codex, 갈라지는 길, 세력·병종·스토리 상호배타까지 한곳에서 비교합니다. **선택 조합 시뮬레이터**에서 연구 카드를 순서대로 완료로 가정하면 룰셋의 방향성 `disables`에 따라 다른 선택지가 즉시 차단되고 이유가 표시됩니다. 과거 완료 연구 ID를 붙여넣거나 4,612개 연구를 검색해 기준 상태에 추가할 수도 있습니다. XPiratez .sav 파일을 브라우저 안에서 직접 읽어 현재 완료 연구(discovered), 영구 배제 상태(researchRuleStatus=2), 연구 일지(researchDiary)의 날짜·획득 경로를 반영합니다. 현재 영구 배제된 연구가 과거 어떤 연구의 직접 disables에 걸렸는지 일지와 룰셋을 교차 대조한 원인 후보도 보여줍니다. 원본 OXCE 엔진에 따라 후속 disables가 이미 완료된 연구 플래그를 제거하고 영구 배제하는 상황까지 계산합니다. 기존 지급품·이벤트 보상의 소급 회수 여부는 별도 룰입니다. 연구의 `dependencies`와 `requires`를 분리하고, 이미 완료한 연구의 `unlocks`로 dependencies를 우회하는 OXCE 엔진 규칙을 반영했습니다. `getOneFree`의 중복 후보는 추첨 가중치로 보존하며, 현재 배제·완료 상태에서 남은 무료 지급 후보(고유 종류 수 및 추첨칸 수)를 보여주지만 실제 RNG 결과를 임의로 지급하지 않습니다. 실물·시설·이벤트·0비용 자동 연구·선행 미완료 조건이 있으면 연구 가능을 확정하지 않습니다. 각 선택의 선행·즉시 보상·후속 해금뿐 아니라 영구 손실과 복구/우회 가능성을 함께 표시하며, 반복 이벤트 경제·방어/탐지·병사 강화·Chaos Saint 공급과 인프라 영향도 연결합니다. 정적 모듈은 `public/captains/`에 있습니다.

영구 선택·분기 DB에는 **22개 선장 선택지의 실제 후속 장점·조건부 보상**을 표시합니다. 기존 시설·능력훈련 표에 빠져 있던 도둑 계급의 **선장의 11(Captain’s 11)** 보상(5개 이벤트 선행 → 토큰 11개 + 연구 플래그, 훈련 1명당 토큰1·글래머21·$100k·500시간)을 대표 이점으로 강조하고, 모든 분기마다 원본 4,612개 연구의 명시적 unlocks 및 792개 이벤트로부터 직접/후속 조건부 경로를 검증해 제공합니다. 목록은 해당 선장을 택했다는 이유만으로 자동 지급된다는 뜻이 아니며, 각 이벤트의 실제 트리거·추첨 가중치·부정 조건·지급품·상호배제와 원본 DB 링크를 별도로 표시합니다. 보상 색인은 경량으로 시작하고 선장별 후속 이벤트 전체 자료는 선택 시 별도 로딩합니다. 모바일에서는 검색 툴바를 비고정 처리하고 표 헤더를 축소하여 실제 스크롤 시 화면 상단 20% 이내만 차지하도록 브라우저 검사합니다.

영구 선택·분기 페이지는 정규화 연구 DB의 `raw.disables` 보유 연구 163개를 86개 연결요소로 전수 감사하고, 내부 PREQ/result 플래그를 제외한 실제 선택축과 경로 결과를 구분해 보여줍니다. Codex의 선택 연구와 실물 Codex 연구에서 발생하는 2중 4색 상호배타도 따로 보여줍니다. 기본 4선장의 Saint 보완색(무모→Green, 멍청→Gray, 게으름→Red, 소심→Gold), G1~G8 Captain×Codex 보너스, Saint 진입 시 중단되는 보너스, Gray/Sore-Ass 등으로 봉쇄되는 부정·도박 이벤트까지 교차표로 정리합니다.

병종/탈것의 **명목 누적 연구량**은 표시된 해금 루트의 `dependencies`와 `requires`를 중복 제거해 합산합니다. OXCE는 이미 비활성화된 선행 연구를 검사에서 제외할 수 있고 `unlocks`, `getOneFree`, 이벤트 직접 지급으로 우회하는 경우가 있으므로, 실제 플레이에서 필요한 연구량은 이 명목값보다 작을 수 있습니다. 페이지는 분기 연구·실물 표본·필요 기지기능·이벤트 조건을 함께 표시해 실제 경로를 따로 판단할 수 있게 합니다.

## 로컬에서 데이터 갱신

Node.js 20+ 기준입니다.

```bash
npm install
npm run build:data -- --source "C:/path/to/user/mods/Piratez"
npm run check              # 전체 DB · 스타팅 · 선택지 · 프런트 자산 통합 검증

# 스타팅만 검증 (원본 이벤트 및 번역 지연/실패/재시도까지)
npm run check:starting

# 선택: 실제 Chrome/Edge에서 14개 DB를 모바일 화면으로 열고
# 검색·상세창·HTTP/자바스크립트 오류까지 검사
npm install --no-save --package-lock=false playwright-core@1.64.0
node tools/check-site-browser.mjs --local
node tools/check-site-browser.mjs --base=https://road2man-cloud.github.io/xpiratez-data-atlas/

# 병사훈련 전용 sidecar 갱신 (다른 DB/Pages 자산에 손대지 않음)
npm run build:trainings -- --source "C:/path/to/user/mods/Piratez"
npm run check:trainings

# 기지시설 DB만 안전하게 갱신·검증
npm run build:facilities -- --source "C:/path/to/user/mods/Piratez" --out public/data
npm run check:facilities -- --data public/data

# 공개 아이템/연구 DB 전용 생성·검증
npm run build:item-research -- --source "C:/path/to/user/mods/Piratez" --out public/items/data
npm run check:item-research -- --data public/items/data
```

개인 로컬 용도로 UFOPEDIA 본문까지 포함하려면 `--include-lore`를 추가할 수 있습니다. 공개 저장소에는 기본 생성물만 커밋하는 것을 권장합니다.

생성기는 Ruleset의 `*.rul` 파일을 읽고 같은 ID의 규칙을 순서대로 병합한 뒤 `refNode` 상속을 펼칩니다. 상세 DB는 청크로 나뉘어 필요한 데이터만 브라우저가 가져옵니다. 병종/탈것 progression은 연구 노드를 `progression-research.json`에 한 번만 저장하고, 연구 경로는 숫자 인덱스 배열, 제조법·이벤트는 ID 참조로 정규화해 동일 정보의 반복 저장을 피합니다.

아이템/연구 공개 DB는 정보 손실 없이 중복을 정규화합니다. 반복되는 한·영 이름은 `entities.json`에 한 번만 저장하고, 연구·제조·역참조는 ID와 경로를 중심으로 연결합니다. `effectiveCoreSources`와 전역 기본값처럼 모든 아이템에 반복되던 메타데이터도 스키마로 이동합니다. 표현 리소스 필드는 `resource-chunks/` sidecar로 분리하며 원본 JSON pointer와 값을 보존하므로 다시 합치면 원본 룰 객체를 복원할 수 있습니다. v.o1.1.1 기준 기존 공개용 생성물 약 58 MiB가 약 30 MiB로 줄며, 검증기는 단일 생성 파일이 50 MiB를 넘으면 실패하도록 막습니다.

## 배포

`public/` 폴더가 완성된 정적 사이트입니다. `.github/workflows/pages.yml`은 main 브랜치 push 시 저장소의 정적 산출물을 검증해 GitHub Pages에 배포합니다. 병종/탈것 progression도 공식 X-Piratez v.o1.1.1 원본으로 로컬 생성·검증한 정규화 JSON을 `public/data/progression*`에 보존하므로 Pages 배포는 외부 다운로드에 의존하지 않습니다. GitHub-hosted runner에서는 ModDB가 403을 반환하므로 `.github/workflows/publish-progression.yml`은 외부 다운로드/자동 재생성 대신 체크인된 compact progression의 구조·크기·smoke test를 검증합니다.

## 권리

사이트 코드에는 MIT 라이선스를 적용합니다. X-Piratez, OpenXcom/OXCE, 원본 X-COM 및 모드 데이터/문구에 대한 권리는 각 원저작자에게 있으며 MIT 라이선스의 적용 대상이 아닙니다. 이 저장소는 팬 제작 기술 참고 도구입니다.

## OXCE 엔진 참조표 (최신 데이터: 2026-10-27)

- **웹 페이지:** [참조표 / reference](./public/reference/) · 배포 URL: https://road2man-cloud.github.io/xpiratez-data-atlas/reference/
- **기계 판독용 번호 정의:** [engine-codes.json](./public/reference/engine-codes.json) — experienceTrainingMode 0–32, damageType 0–19, damageAlter.RandomType 0–9, 성장 상한 용어
- **최신 게임 X-Piratez 2.1 아이템:** [items.json](./public/reference/items.json) — 현재 설치본 v.o2의 경험치 모드 직접 선언 306개. 참조표에는 이 데이터만 표시하며 이전 버전 데이터는 제공하지 않습니다.
- **병종별 복셀 높이:** [병종 29종·방어구 540종 참조표](./public/reference/#unit-voxels) · [unit-voxels.json](./public/reference/unit-voxels.json) — 병종의 서기/무릎 복셀 높이와 방어구 착용 시 실효 높이, 점유 타일, 무릎 허용 선언, **서서 사격 및 무릎 사격의 각 출발 Z**, 방어구별 **충돌 마스크 ID와 실측 16×16 마스크 단면**(블러드하운드 탑승 로크나르: 9×9 범위·61복셀/층 등)을 원본 룰·LOFTEMPS.DAT SHA-256과 함께 제공합니다. [2×2 장비 전수표](./public/reference/#large-unit-voxels)는 아군이 착용 가능한 46종을 각각 한 행으로 정리하고 32×32복셀 내 실점유 780개/층, 금지된 무릎 사격, 착용 병종별 서기·총구 높이를 모두 대조합니다.
- **검증:** `npm run check:reference`; 별도 실제 브라우저 QA는 `npm run check:reference:browser`. 정적 체크는 `npm run check` 및 Pages 배포 검사에도 포함됩니다.

**GPT 검색 순서:** engine-codes.json에서 번호 의미를 확인 → 최신 게임 [items.json](./public/reference/items.json)에서 `i` (원본 ID), `m` (experienceTrainingMode), `f` / `l` (원문 출처) 확인. `null`로 표시한 `damageType`이나 `power`는 0이 아니라 **해당 아이템 블록에 직접 선언되지 않았다**는 뜻입니다. 상속·탄약·오버라이드·스크립트 적용 결과는 별도 검증해야 합니다.

아이템 번호표는 2026-10-24, 병종·방어구 복셀 참조표는 **2026-10-27에 확인한 X-Piratez 2.1 (v.o2), OXCE 8.7.1** 설치본을 기준으로 합니다. `node tools/build-data.mjs --unit-voxels-only --source <.../user/mods/Piratez>`로 복셀 JSON을 재생성할 수 있으며 자세한 근거는 [검증 문서](./docs/reference-voxels-2.1.md)에 있습니다. 버전 선택기와 구버전 데이터는 제거했습니다. 새로운 게임 업데이트가 나오면 `items.json`과 브라우저용 `items.js`를 함께 갱신하고 `npm run check:reference`로 검증해야 합니다. `extendedExperienceAwardSystem: true` 및 기절·정신지배 시 경험치 제한도 함께 고려해야 합니다.
