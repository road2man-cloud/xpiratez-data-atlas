## 측정 방법

GitHub Ubuntu runner의 실제 headless Chrome/Chromium 브라우저로 각 조건을 3회 실행하고 중앙값을 사용했다. 매번 새 context를 만들고 캐시를 비활성화했다. 데스크톱은 1440×900, 10 Mbps, 지연 40ms, CPU 1배; 모바일은 390×844, 1.6 Mbps, 지연 150ms, CPU 4배 감속이다. 실제 휴대폰/Safari 실측을 대신하는 수치는 아니다.

같은 정적 서버로 전후 버전을 제공했다. 일반 JSON/JS/CSS/HTML은 HTTP gzip으로, 이미 압축된 .gz 파일은 그대로 전송했다. 첫 실제 데이터 행이 만들어지고 두 번의 animation frame이 지난 시점까지 측정했다. 전송량은 Resource Timing의 encodedBodySize이며 공통 플레이 가이드 teaser도 포함한다. 비압축 파일 크기와 구분해야 한다. Long task는 50ms 이상 메인 스레드 작업의 브라우저 관측값이다. CDP ScriptDuration은 비동기 작업 전체 CPU 시간을 대표하지 않으므로 원본 수치와 long-task/layout 수치를 함께 기록했다.

## 적용 내용과 비용 이동

- 병종: 초기에는 1.09MB 원본 크기의 목록 데이터를 읽는다(배포 gzip 72,678 bytes). 2.46MB 강화 조합 세트와 전체 최종 조합 계산은 표를 선택할 때 시작한다. 프로필 사이와 분기 검사 배치 사이에 브라우저에 제어권을 넘긴다. 결과, 검색 텍스트, 데이터셋, 동적 조합을 재사용한다.
- 병종 최종 조합 최초 준비: 데스크톱 1.40초, 모바일 조건 6.49초. 비용을 없앤 것으로 해석하면 안 된다. 다시 표를 선택했을 때 계산 measure가 1회뿐임을 검증했다.
- 병사훈련: SoldierBonus 이름은 전부 유지하고 실제 사용하는 특성의 효과만 포함한다. 연구/이벤트/아이템 공급 판정 자료는 원형 그대로 유지한다. 별도 연구 그래프 + gates 대신 검증된 compact choice index를 사용한다. rawRule은 상세에서 로드한다. 분기/이벤트 접근 판정 캐시는 매 시나리오 변경 때 폐기한다.
- 제조: 목록에서 상세 전용 필드와 전체 검색 코퍼스를 분리한다. 첫 목록은 gzip 163,065 bytes, 검색 코퍼스는 첫 입력 때 gzip 204,957 bytes를 추가로 읽고 재사용한다. 처음 검색할 때는 추가 로딩이 발생한다. 원래 searchText를 그대로 보존해 재료·시설·연구 검색을 유지한다. 숫자 formatter와 정렬 collator를 재사용하고, 상세/인사이트 요청은 병렬 및 promise 캐시로 처리한다. 빠른 상세 전환 후 이전 응답이 덮어쓰는 것을 방지한다.
- 기체: 기체 능력/슬롯/공통 분기/검색용 제조·이벤트 이름만 초기 로드한다(gzip 27,353 bytes). 전체 획득 근거와 연구 라벨은 상세에서, 전체 연구 노드는 별도 요청에서 로드한다.
- offscreen rendering 힌트, 입력 debounce, 실패 요청 재시도, 기존 JSON fallback을 추가했다. canonical 파일은 유지했다. 새 runtime은 기존 build 명령으로 재생성되며 shared check에서 검증된다.

## 기능 검증

- npm run check:all: 전체 카탈로그, 4,612 연구, 방향성 배제와 이벤트 경로, 하드캡 검사 통과.
- 전체 최종 강화 조합 1,418개의 수치·훈련 순서·랜덤 구간을 이전 계산 코드와 정확 비교.
- 제조의 목록/정렬 필드 및 2,158개 searchText, 훈련 원본 83개, 사용 특성 효과, 모든 연구·이벤트·공급 조건의 보존 확인.
- 기체 96종의 능력치/슬롯/분기/별칭과 제조·이벤트 검색 이름 보존 확인.
- gzip 스트림 실제 해제, 동시 요청 1회, 미지원 환경의 원본 JSON fallback, HTTP 실패 후 재시도를 Node Web API로 별도 실행해 검증.
- 데스크톱·모바일 4개 페이지의 cold A/B에서 무결과 검색 후 목록 복원 및 최종 계산 캐시 검사 통과.
- 기존 모바일 브라우저 회귀 검사 전체 14/14 통과. 검색, 상세/딥링크, 정렬, 선행 훈련 추가, 선장 경로, 상호배제, 실효 스탯과 성장 하드캡 검증을 포함한다. 브라우저 오류와 HTTP 실패 0건.

열려 있는 PR #18의 미병합 변경은 이 검증 범위에 포함하지 않았다. 미래 데이터/계산 규칙 변경 시 runtime을 재생성하고 수치 비교 및 브라우저 검사를 다시 실행해야 한다.
