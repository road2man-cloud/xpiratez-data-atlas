## 사용자가 실제 사용하는 변경

제조 경로 작업대에서 가상 조달 계산을 마치고 **후속 부족 재료 계산 및 통합 작업표 갱신**을 실행하면, 공통 검토 작업 목록에 이전부터 존재하던 선행 의존 그래프와 함께 최종 조달 원장, 최종 연구·시설 조건 체크리스트의 근거를 표시한다.

- 재료 작업에는 **입력 재고**, **최초 가상 확보**, **후속 단계 가상 확보**, **누적 가상 확보**, **확보 후 가상 재고**, **남은 부족**, **단계별 가상 확보**를 분리 표시한다.
- 해당 재료가 조달 원장에 등장하지 않으면 **원장 미기재**로 표시한다. 0개나 구매 가능 상태로 임의 해석하지 않는다.
- 연구·시설·규칙 조건에는 체크리스트가 가진 **조건 종류**, **상태명**, **세이브·규칙 근거 설명**, **다음 확인할 동작**을 그대로 표시한다.
- 조건 체크리스트에 대응하는 항목이 없으면 **별도 근거 미기재**로 표시한다.
- **남은 부족 재료**, **미검토 연구·시설 조건**, **메모 있는 작업** 필터를 추가한다. 기존 공통·반복·단독 및 미검토 필터는 그대로 유지한다.
- 공통 작업 목록에서 검토 체크와 **300자 메모를 직접 편집**한다. 저장 대상은 기존 `routeBatch.actionReviewed`, `routeBatch.actionNotes`이고, 개별 작업표 및 JSON·CSV 저장 기능과 자료를 공유한다.
- 재료에서 **조달 원장 상세**, 재료·조건에서 원래 통합 작업표, 관련 제조식으로 이동한다.
- **공통 검토·조달 근거 CSV**와 **공통 검토·조달 근거 JSON**은 화면의 최대 100개 행과 무관하게 전체 데이터를 내보낸다. CSV의 사용자 메모는 스프레드시트 수식으로 실행되지 않도록 위험한 접두사를 중화한다.

## 데이터 보호

원본 세이브·게임 규칙·번역 파일·OXCE 엔진은 변경하지 않는다. 조달 수량은 **모두 가상 계획**이며 실제 보유·구매 가능성을 보장하지 않는다. 조건 상태는 체크리스트의 명시 근거를 보여주는 용도이고, 사용자 검토 표시를 게임 내 연구/시설 완공으로 취급하지 않는다.

동일한 제조 목표의 v.o2 원장과 체크리스트만 받으며, 다른 제조 목표의 원장·과거 1.1 자료·불일치한 원장 합계는 거부한다.

검토 기록은 브라우저 작업대 메모리에 있으며, 영구 보존하려면 기존 검토 JSON 내보내기를 사용해야 한다.

## 검증 범위

신규 변경된 모듈에 대한 Node 단위 검사를 수행하고, 이후 전체 제조 계산기 테스트를 실행한다. 브라우저의 실제 UI 구동과 공개 웹 배포, `main` 병합, OXCE 엔진 제조 명령 연동은 별도이며 자동 테스트 통과를 근거로 완료라고 표시하지 않는다.
