# Project X-Piratez 3D (가칭) — 프로젝트 헌장

- 출범일: 2026-11-01
- 상태: **기술 타당성 검증(Feasibility), 구현 검증 전**
- 현재 기준 저장소: `road2man-cloud/xpiratez-data-atlas`
- 원칙: **기존 X-Piratez 데이터 아틀라스를 유일한 규칙 참조점으로 재사용한다.** 독립된 중복 룰 DB를 새로 만들지 않는다.
- 이 문서는 기술 기획이며, **3D 엔진이나 플레이 가능한 프로토타입이 완성되었다는 뜻이 아니다.**

## 1. 북극성

> X-Piratez의 깊이 있는 전술 규칙, 장기 성장, 연구·제조·경제·상호배타 구조를 보존하면서, Silent Storm에서 체감했던 입체적 공간·엄폐·파괴·관통의 상호작용을 가진 3D 전투를 구현한다.

이 프로젝트는 단순한 2D 스프라이트의 3D 치환을 목표로 하지 않는다. 총탄, 엄폐, 구조물 파괴, 층간 전투, 이동 경로, 시야를 **하나의 일관된 전투 세계**에서 작동하도록 만드는 것이 핵심이다.

## 2. 확정된 기술적 사실과 미검증 가설

### 확인된 사실

- Silent Storm의 공개 소스에는 폴리곤 지오메트리를 복셀 격자에 투영하는 렌더러(`CExplVoxelRenderer`, `CVisionVoxelRenderer`), BSP 기반 충돌 검사, 공간 변경 추적기, 다층 경로 탐색 자료가 있다.
- 핵심 근거:
  - [Nival 소스 — aiVoxelRender.cpp](https://github.com/nival/Silent-Storm/blob/main/Soft/Andy/Jan03/a5dll/Main/aiVoxelRender.cpp)
  - [Nival 소스 — aiVoxelRender.h](https://github.com/nival/Silent-Storm/blob/main/Soft/Andy/Jan03/a5dll/Main/aiVoxelRender.h)
  - [Nival 소스 — BSPCollider.h](https://github.com/nival/Silent-Storm/blob/main/Soft/Andy/Oct02/src/BSPCollider.h)
  - [Nival 소스 — aiMap.cpp](https://github.com/nival/Silent-Storm/blob/main/Soft/Andy/Jan03/a5dll/Main/aiMap.cpp)
- 본 저장소에는 X-Piratez 및 OXCE 규칙 데이터 검증·역참조·정규화 체계가 이미 축적되어 있다. **데이터 버전을 혼합하지 않는다.**

### 아직 증명하지 못한 가설

- H1: X-Piratez / OXCE의 전투 규칙을 3D 공간 쿼리 인터페이스로 분리하여 원본 수치·순서를 충실히 재현할 수 있다.
- H2: 폴리곤 표면 표현 + 복셀/공간 부피 판정을 혼합하면 부분 파괴 후 시야·탄도·이동 경로의 일관성을 유지할 수 있다.
- H3: 이 구조가 다양한 맵·유닛·장비를 추가해도 유지보수 가능한 성능과 데이터 계약을 제공한다.
- H4: 상용·비상용 여부와 상관없이 장기간 지속 가능한 권리 구조를 확립할 수 있다.

**가설이 반증되면 구현 방식을 바꾸며, 플레이 감각만으로 성공을 선언하지 않는다.**

## 3. 라이선스 및 권리 경계 — 첫 번째 의사결정 게이트

Nival의 Silent Storm 소스 라이선스는 비상업적 이용만 허용하고, 권리자의 재량적 철회 및 철회 공지 후 3일 내 이용 중지 조항을 포함한다.
[원문 LICENSE.md](https://github.com/nival/Silent-Storm/blob/main/LICENSE.md)

따라서 **Nival 코드를 OXCE 코드베이스에 복사하거나 임의로 결합해 배포하지 않는다.** OXCE/OpenXcom의 라이선스와 Nival 라이선스의 결합 가능성은 별도 검토와 필요 시 권리자의 명시적 허락이 필요하다. 실행 파일/프로세스 분리만으로 라이선스 문제가 자동 해결되는 것도 아니다.

- **연구 트랙:** Silent Storm의 공개 소스를 읽고 자료구조·설계 원리를 평가한다. 코드 재사용 허락으로 오해하지 않는다.
- **제품 트랙:** 장기적으로 권리 의존성이 낮은 독자 구현 또는 적법한 공개 라이선스 엔진을 후보로 둔다. Nival 자체 엔진 채택은 법률 검토 및 권리 확인 이전에 확정하지 않는다.
- X-Piratez 및 X-COM의 원본 이미지, 음악, 맵, 설정 텍스트를 무단 복제·공개 저장소에 배포하지 않는다. 프로토타입은 독자 제작한 기초 도형과 대체 이름으로 출발한다.
- 공개 배포의 가능 여부는 별도 판단한다. 초기 산출물은 **원본 게임 자산이 없는 테스트 코드, 추상 규칙 매핑, 결과 로그**로 한정한다.

## 4. 설계 규율: 원본 룰과 물리 표현의 분리

아래 계약은 제안이며, 아직 구현 완료 사실이 아니다.

```text
Canonical game rules (OXCE revision + X-Piratez version + source hash)
        |
        v
TacticalRuleAdapter  -- AP/TU, 공격 선택, 명중, 방어, 피해, 턴 처리
        |
        v
SpatialQuery          -- 3D 레이, 충돌 구간, 재질, 엄폐, 높이, 접근성
        |
        v
WorldGeometry         -- 폴리곤 표면 + 목적별 복셀/공간 인덱스
        |
        v
WorldDelta            -- 벽·문·바닥 변경 -> 충돌/시야/경로 재계산
        |
        v
DeterministicReplay   -- 초기 상태, 규칙 버전, RNG seed, 선택 행동, 결과 기록
```

**반드시 보존할 것:** 원본 확률·피해·방어·능력치·시간 단위·처리 순서를 가능한 한 기계적으로 추적한다. 원본에 없는 공간 자유도(새 사선·붕괴·연속 좌표)는 **의도적으로 달라진 규칙**으로 명시하고 검증한다. 단순히 비슷한 피해량을 낸다는 이유로 원본과 동일하다고 표시하지 않는다.

새 구조는 기존 사이트의 전투 시뮬레이터, 규칙 식별자, 버전·출처 추적을 읽어야 한다. 독립된 제2의 '원본' 판정 체계를 만들지 않는다.

## 5. 첫 번째 검증 작품: 한 개의 3D 전투실

**최소 장면**
- 2층짜리 작은 테스트 건물, 계단/층간 통로 1개, 문 1개
- 서로 다른 재질의 벽 2개와 부분 파괴 가능한 엄폐물 1개
- 대원 1명, 적 1명, 무기 유형 2개, 폭발물 1개
- 저작권 문제가 없는 임시 모델과 데이터
- 사용자 시점 회전, 층 표시, 원점·타격 지점 확인용 디버그 HUD

**필수 5개 실험**
1. 수직 사격: 1층과 2층 사이의 레이·엄폐·바닥 충돌을 확인한다.
2. 재질 관통: 표면 충돌 위치와 실제 관통/피해 규칙이 일치하는지 확인한다.
3. 구조물 파괴: 폭발 전후의 지형 상태를 기록한다.
4. 동기화: 벽 파괴 직후 같은 시뮬레이션 상태에서 시야·사격·경로 탐색이 함께 갱신되는지 확인한다.
5. 룰 보존: 파괴가 없는 동일 입력을 원본 OXCE 계산과 대조하고, 일치/차이/미실행을 분리한다.

**실험 결과의 증거 등급:** `원본 코드 확인` / `동일 입력 실행 검증` / `독립 구현 테스트` / `추정` / `미검증`. 추정을 성공한 실측 결과로 표기하지 않는다.

## 6. 검증의 반증 조건 (stop / pivot)

다음 중 하나라도 나타나면 '기술 완성'을 선언하지 않는다.

- 원본 OXCE 전투 공식의 일부를 의도치 않게 바꾸거나, 실행 없이 동일성으로 표시한다.
- 구조물 파괴 후 눈에 보이는 지형과 충돌·시야·경로 자료 사이에서 지속적인 불일치가 발생한다.
- RNG seed, 실행 규칙 버전, 테스트 입력이 불명확해 결과를 재현할 수 없다.
- 권리 상태가 불안정해 독자 배포·장기 유지가 허용되지 않는 구현에 핵심 데이터나 엔진을 가둔다.
- 새 맵이나 신규 물체를 추가할 때 충돌·시야·길찾기 등을 개별 임시 패치해야만 동작한다.

판정: 원인 특정 후 재설계. 범위 축소는 허용하지만 근거 없는 성공 선언은 금지한다.

| 0. 헌장/권리 확인 | 본 문서, 권리 표, 기술 선택 기록 | Nival/OXCE/X-Piratez 사용 경계 명확 |
| 1. 전투 규칙 계약 | 원본 OXCE 입력·계산·출력·시드 기록 스키마 | 실제 버전과 원본 수식·출처 연결 |
| 2. 공간 프로토타입 | 2층 건물, 기본 폴리곤·공간 쿼리, 복셀 표현 실험 | 레이 충돌과 높이/엄폐 확인 |
| 3. 파괴의 일관성 | 월드 변경 이벤트와 공간 캐시 무효화 | 벽 파괴 즉시 시야·탄도·경로 동기화 |
| 4. 전투 재현 | 1대1 전투, 무기 2종, 폭발, 결정적 리플레이 | 원본과 의도된 차이만 존재함을 보고 |
| 5. 수직 절편 | 실제 플레이 가능한 1개 소형 임무 | 턴 종료까지 재현·디버깅 가능한 빌드 |

**현 단계:** 단계 0 시작. 아직 1~5 단계 완료를 주장하지 않는다.

- [ ] 위 5개 실험에 대한 입력/출력/반증 조건을 JSON 테스트 계약으로 정의한다.
- [ ] 엔진 후보를 비교해 **첫 실험을 위한 단 하나의 구현 기반**을 고른다. 선택 전에는 Nival 코드를 복사하지 않는다.

## 9. 변경 원칙

- 단일 의사결정 문서와 출처를 유지한다. 같은 사실을 다른 위치의 별도 '정답'으로 복제하지 않는다.
- 기존 데이터 아틀라스의 작동 중인 서비스와 검증 게이트를 손상시키지 않는다.
- 기술 선택은 반증 가능한 실험 결과가 있을 때만 확정한다.
- 큰 비전을 유지하되, 매 단계는 작동하는 결과물과 재현 가능한 테스트로 끝낸다.
