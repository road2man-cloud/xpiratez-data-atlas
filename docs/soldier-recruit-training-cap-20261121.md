# X-Piratez v.o2 병종 DB — 모집 N회·능력치 요건 검토 K명 제한

**기준일:** 2026-11-21
**작업 저장소:** `road2man-cloud/xpiratez-data-atlas` / `main`
**수정 범위:** 기존 12종 병종 DB 상세 비교 화면 및 조건부 출생 선발선 엔진

## 실제 구현

1. **`public/soldiers/modern/recruit-training-cap.js` (신규)**
   - 독립 신규 추첨 N회(1~10,000), 그중 초기 선발선 통과 대원의 능력치 요건 검사 상한 K명(1~200), 선발률 q, 선발 집단의 시술 능력치 요건 통과율 g를 입력받는다.
   - 선발자가 S명 생성되면 S ~ Binomial(N,q). 등록 경로의 능력치 요건을 최대 min(S,K)번 검토하는 모델에서 하나라도 통과할 확률:
     `P = sum_{s=0}^{N} Binom(N,s;q) * (1 - (1-g)^min(s,K))`.
   - 구현은 K 미만 항과 K 이상 항을 나눠 **정확한 유한 이항합**으로 계산한다. 로그 팩토리얼을 사용해 q가 0 또는 1에 가까운 큰 N에서도 단순 P(S=0) 재귀가 언더플로하는 문제를 방지한다.
   - K>=N일 때 무제한 검사 `1-(1-q*g)^N`과 동치가 된다.
   - **검토 상한 초과 가능성** `P(S>K)`와 평균 상한 사용 `E[min(S,K)]`, 성공 시 중단하는 모델의 평균 검사 인원 `P/g` (g>0)을 산출한다. g=0이면 평균 검사는 `E[min(S,K)]`.
   - 주의: 검토하는 사건은 원본 시술 경로의 **능력치 요건 충족**이고, 실제 게임의 훈련 성공·연구·자원 소모가 아니다.

2. **`public/soldiers/modern/route-birth-screen-frontier.js`**
   - 기존 한 능력치 컷오프 전수 탐색에 선택적 `trainingSlots`를 추가했다.
   - 최종 능력치 조건부 기대값과 **K명 제한하의 획득 확률**을 두 축으로 최적화한다. K가 없으면 기존 무제한 검사 결과를 그대로 유지한다.
   - 각 초기 선발선에서 K명 제한 성공 확률, 무제한 성공 확률, 검토 상한 초과 확률, 평균 검사 인원과 이론적 독립 신규 추첨 횟수를 명시적으로 분리한다.
   - 특정 선발선의 조건부 최종 평균은 N/K 가정으로 바뀌지 않으며, N/K는 선택 시 필요한 후보 확보 가능성에만 작용한다.

3. **`public/soldiers/modern/route-birth-screen-view.js`, `app.js`, `index.html`, `origin-catalog.css`**
   - 기존 등록 경로 상세의 선발선 역산 UI에 **신규 추첨 N**과 **능력치 요건을 검토할 선발 대원 최대 K명** 입력을 배치한다.
   - 같은 테이블에 무제한 검사와 K명 제한 확률, K명 초과 인원 발생 확률, 성공 시 검토 중단 모델의 평균 검사 인원을 제공한다.
   - 기존 `1/(q*g)`는 K 제한에서의 모집 예상 횟수로 취급하지 않고 **검토 무제한 모델의 값**으로만 표시한다.
   - 권장 선발선은 상세 표 상단 버튼으로 바로 기존 12종 초기 입력에 반영된다. 반영 시 다른 11종 선발 입력은 명시적으로 초기화한다.
   - 동일 출생처에서 다른 등록 시술 후보를 열어도 N/K 및 선택 목표를 유지한다. 선택값이 바뀌면 예전 출력의 유효성을 취소하고 재계산을 안내한다.

4. **자동 검사**
   - `tools/check-recruit-training-cap.mjs`은 작은 N에 대한 독립 삼항사건 완전열거(선발 탈락/선발-요건 불충족/선발-요건 충족)와 유한 이항합을 비교한다. 극단 q/g, N=10,000, K=1 및 K=100 등의 계산을 확인한다.
   - `tools/check-route-birth-screen-frontier.mjs`은 동일 등록 경로에서 K=1 제약을 걸었을 때 최적 신병 초기 선발선이 달라지는 사례와 K>=N 동치성을 비교한다.
   - `tools/check-route-table-browser.mjs`은 신규 입력 UI, K 제한 출력, 후보 이동 후 설정 유지, 추천 기준 반영을 실제 브라우저에서 실행한다.

## 의사결정 사례 (원본 병종의 실제 확률 아님)

출생 TU가 {5,6,7}을 각각 1/3로 추첨하며, 시술 능력치 요건이 TU 7 이상이라고 가정하자.

- 신규 병사를 N=10명 생성하고 선발된 K=1명만 시술 능력치 요건을 검사할 수 있다면:
  - TU 5 이상 전원 선발: 첫 선발자 1명이 TU 7 이상일 확률 33.33%.
  - TU 7 이상만 선발: 10명 중 적어도 한 명이 TU 7 이상일 확률 `1-(2/3)^10` ≈ 98.27%.
- K>=10명이면 두 선발선의 총 결합 성공 확률은 동일하게 ≈ 98.27%가 된다.

이것은 **능력치 요건 검토 인원 제한**이 있을 때에만 높은 출생 선발선이 성공 확률을 개선할 수 있음을 보여준다. 모집·시술·자원 비용이 동일하다는 뜻은 아니다.

## 중요한 한계

- K는 사용자가 가정한 **능력치 요건 검사 가능 대원 수**다. 실제 시술 횟수나 비용·시간을 자동으로 원본에서 유추한 값이 아니다.
- 통과율은 원본 출생 RNG와 입력한 시술 경로의 **능력치 요구조건**에 한정된다. 연구·계급·재료·시설·게임 내 실제 모집 난이도와 실제 전투 경험치 생성 확률은 별도다.
- 각 선발선은 초기 실효 능력치 **한 종의 최소값**만 탐색한다. 12종 조합의 전역 최적성을 주장하지 않는다.
- 이미 등록된 경로의 **시술 순서**는 바꾸지 않는다. 이전 작업의 코르트 독립 분리, 연구 분기, 초기 영구 보너스, reset 및 조건부 상한 계산을 유지한다.
- 신규 브라우저·계산 검사에서 실패하면 반영했다고 주장하지 않는다. GitHub 배포는 커밋과 원격 SHA 확인 후에만 완료로 기록한다.
